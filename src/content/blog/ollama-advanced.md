前几篇够日常用了。想再进一步，主要是三件事：把常用的提示词固化下来、调一下参数、搞清楚模型精度和硬件的关系。

## 这篇文章的目标

- 用 Modelfile 把一个"定制助手"（固定人设 + 参数）固化下来，以后直接跑，不用每次重说；
- 看懂模型精度（量化）是怎么回事，以及它和内存的关系；
- 知道怎么按自己电脑的内存选模型，而不是盲目追大。

## 用 Modelfile 固化提示词

不想每次对话都重复说"你是一个帮我读代码的助手"，可以写个 Modelfile（就是个记配置的文本文件）：

```
FROM qwen2.5:7b
SYSTEM """
你是一个帮我读代码、写技术笔记的助手，回答简短直接，不废话。
"""
PARAMETER temperature 0.3
PARAMETER num_ctx 4096
```

然后建一个自己的模型：

```bash
ollama create myhelper -f Modelfile
ollama run myhelper
```

以后直接跑这个定制模型，系统提示词和参数都带上了。

## 关键参数

- `temperature`：随机性。低了稳、高了跳。写代码、查事实这类任务调低（0.2–0.4），头脑风暴可以调高。
- `num_ctx`：上下文窗口大小。越大能记住越长的内容，但也更占内存。

## 量化到底怎么选

模型内部是一大堆数字（权重），这些数字的"记录精度"可以不一样：

- `fp16`：最准，但体积最大；
- `q8_0`：接近无损，体积差不多减半；
- `q4_K_M`：更小更快，质量略有损；
- 再往下（q2 之类）：明显变笨。

笔记本日常用 `q4_K_M` 或 `q5_K_M` 比较稳，兼顾速度和质量。

## 内存/显存是硬约束

macOS 上 Ollama 用 Metal 走苹果芯片的图形算力来跑模型，但模型权重主要吃的是统一内存；有独显的机器（比如带 N 卡的 Windows/Linux）就走显卡显存。模型一旦放不进内存，就会掉到 CPU 上跑，变得很慢，甚至直接加载失败。

所以选尺寸先看内存，不是看"我想用多大"。先把 7B + q4 跑通，再按需要往上加或者往下减。

一句话收个尾：本地模型的好处是可控，代价是要自己管资源。先跑通，再调，别一上来追顶配。
