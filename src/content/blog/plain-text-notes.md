过去几年，我几乎试遍了市面上的"第二大脑"工具：Notion 用来搭数据库，飞书文档用来协作，印象笔记用来囤网页剪藏。它们都很强，但用了三年后我发现一个扎心的事实——**我写得越多，反而越不敢动这些笔记**。

不是因为懒，而是因为风险：一旦平台调整付费策略、关闭某个功能，或者我换了一个不兼容的生态，这几年的积累就可能变成一座搬不走的孤岛。

于是我把整套笔记系统重写为纯文本，用 Markdown 文件 + Git 来管理。这篇文章记录我这么做的原因，以及它如何改变了我的工作流。

## 我离开"全能笔记"的理由

那些"全能"工具最大的卖点，往往也是最大的陷阱：**它们在替你定义结构**。

当你想记一条灵感，它先问你"放进哪个数据库、打什么标签、关联哪个项目"。笔记还没写，认知负担已经先交了一次税。更隐蔽的是，富文本的格式（颜色、嵌套块、嵌入式看板）把内容锁死在它自己的渲染器里——你导出的东西，只有它能完美打开。

> 工具应该为内容服务，而不是让内容为工具的存在而付费。

## 纯文本的三条铁律

我把判断一个笔记格式是否"可持续"的标准简化为三条：

1. **可读**：十年后，不需要任何专用软件，用系统自带的文本编辑器就能读。
2. **可移植**：能无损地从一个工具搬到另一个工具，格式不丢失语义。
3. **可版本化**：每一次修改都能被 Git 记录、对比、回滚。

Markdown 恰好同时满足这三点。它是纯文本，被几乎所有工具支持，并且天然适合 `git diff`。

## 我的目录结构

我没有追求"一个完美的分类法"，而是用最朴素的方式组织：

```text
notes/
├── inbox/        # 临时想法，先丢进来
├── topics/       # 成型的主题笔记
│   ├── astro.md
│   └── zettelkasten.md
├── logs/         # 每日流水
└── index.md      # 手动维护的 MOC（内容地图）
```

关键不是结构多精巧，而是**让检索代替整理**。我几乎不在写的时候分类，而是写完之后靠全文搜索去找。

## 检索比整理更重要

在纯文本世界里，整理是可选的，检索是必赢的。一条命令就能横跨整个知识库：

```bash
rg -n "zettelkasten" notes/ --hidden
```

`ripgrep` 的速度让"翻找"这件事消失。我不再维护复杂的标签体系，因为搜索比记忆标签更快、更准确。

## 用 Git 给笔记上版本

这是纯文本方案最被低估的优势。每一条笔记都是一个被版本管理的小文件：

```bash
git add notes/topics/astro.md
git commit -m "notes: 补充 Astro 内容集合的 frontmatter 写法"
```

我可以随时 `git log` 看一条思考是怎么演化的，也能在写崩了之后 `git checkout` 回到昨天的版本。笔记从"怕改坏"变成了"随便改"。

## 小结

纯文本不会让我的笔记更漂亮，但它让我的笔记**更自由**。它没有花哨的看板，却给了我三样更贵的东西：可读性、可携带性、可回退性。

如果你也正被某个"全能笔记"绑架，不妨从一个 `notes/` 文件夹开始，先搬最重要的十条，体验一下"内容真正属于自己"的感觉。
