本地跑大模型是件很吃机器资源的活儿。模型越大，要的显存和内存越多；机器不够，硬拉一个跑不动的模型，不是卡死就是直接崩。

所以在装 Ollama、拉模型之前，先花五分钟看清自己电脑到底有什么料。用 Windows 自带的工具就能把最关键的三样——内存、CPU、显卡——看明白，再对应到"我能跑多大的模型"。

不需要装任何额外软件，系统自带的就够。

## 第一步：看内存（最基础的）

内存是整个本地模型的地基。模型权重要先把住进内存里，内存不够，连加载都加载不进来。

按 `Ctrl + Shift + Esc` 打开**任务管理器**，点「性能」标签，再选**内存**：

- 右上角看「已使用 / 总数」，知道你一共多少内存（8GB、16GB、32GB）；
- 下面看「速度」，一般 2400MHz 往上都还算正常。

简单说：

- **8GB**：勉强，只能跑很小的模型，且系统自己还要占掉一部分，实际很紧；
- **16GB**：舒服，7B 级别随便跑；
- **32GB 及以上**：能上 14B、甚至更大的，还能同时开着别的软件不卡。

## 第二步：看 CPU

还是任务管理器 → 性能 → **CPU**：

- 看核心数（逻辑处理器那行），越多并行越好；
- 看「基础速度」，单位是 GHz。

CPU 也能跑模型，只是比显卡慢不少。没有独显的机器，基本就是靠 CPU + 内存硬扛。所以 CPU 不强也别灰心，能跑，只是慢一点。

## 第三步：看显卡（决定能不能 GPU 加速，最关键）

这一项是本地模型体验的分水岭。显卡有**专用显存**的话，模型可以丢到显存里跑，速度比 CPU 快一个量级。

任务管理器 → 性能 → **GPU**：

- 看「**专用 GPU 内存**」这一项。这就是独立显存，越大越好；
- 很多轻薄本只有「**共享 GPU 内存**」（和内存共用），没有专用显存——这种基本还是靠 CPU 跑，别指望显卡加速了。

对照一下：

| 专用显存 | 大致能跑的模型 |
| --- | --- |
| 4GB 左右 | 7B 的 Q4 量化版，将将能跑 |
| 8GB | 7B 流畅，可以试 14B 的 Q4 |
| 16GB 及以上 | 14B / 34B 的 Q4 都没问题 |

如果你看到的是「共享 GPU 内存」、专用显存是 0，那就按 CPU + 内存的路线走，选小一点的模型。

## 想看得更细：dxdiag 和 PowerShell

上面三步够日常用了。想确认具体型号，还有两个系统自带的办法：

**dxdiag**（开始菜单直接搜就能打开）：

- 「系统」标签看 CPU、内存总量；
- 「显示」标签看显卡型号和显存。

**PowerShell**（开始菜单搜 PowerShell，右键「以管理员身份」不一定需要）：

```powershell
Get-ComputerInfo -Property "*Memory*", "*Processor*"
```

或者更直观的一行：

```powershell
systeminfo | findstr /C:"内存" /C:"处理器"
```

这俩能拿到比任务管理器更书面的型号信息，查驱动、问人、对参数时用得上。至于 CPU-Z、HWiNFO 这类第三方工具能看得更细，但新手不是必须，系统自带的已经够判断了。

## 装完 Ollama 之后，反过来验证

等后面装好 Ollama、拉了模型，还可以反过来确认模型到底跑在哪：

- 命令行里 `ollama ps`，能看到当前跑着的模型、占用多少显存；
- 任务管理器 → 性能 → GPU，能实时看到显卡占用是不是上去了——上去了就说明模型确实在显卡上跑，没上去就是回退到 CPU 了。

## 怎么把硬件对应到选模型

把上面的信息拼起来，粗粒度判断：

- **无独显 + 16GB 内存**：选 7B 的 Q4 量化（比如 `qwen2.5:7b`，默认就是量化版），CPU 模式慢慢跑；
- **4GB 显存**：7B 的 Q4，会走显卡，比纯 CPU 快；
- **8GB 显存 + 16GB 内存**：7B 很流畅，可以试 14B 的 Q4；
- **16GB+ 显存**：往上加，14B、34B 的 Q4 都能玩。

这里提一句「量化」：同一个模型常带 `q4`、`q8` 这种后缀。Q4 是压得更小、更省资源、质量略降；Q8 更大更准、更吃机器。新手先用 Q4 跑通整个流程最稳妥。

看清楚自己的机器之后，下一篇就去把它装起来。
