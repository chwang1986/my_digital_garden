我本机用 Ollama 跑起了 qwen3.8，就想顺手把"做 PPT"这件日常活交给它。这篇先把目标写清楚，再列几条能走的路，作为后面一系列文章的起点——具体实现留到后面一篇篇补，每篇都当实验记录写。

## 我要解决什么

日常做 PPT 基本是两种场景：

- 零散的、一次性的汇报：直接用 Office 的 PowerPoint 手动做；
- 成系列的、偏技术的讲义：用 Overleaf 的 Beamer（LaTeX）来做，公式和版本管理都方便。

现在本机有了能聊的大模型，我想做的是：把"聊天记录"或者"一份 md 大纲"丢给它，它帮我产出能用的 PPT。最好完全本地、不联网，符合我一贯的隐私偏好。

这次先只讨论"做 PPT"这一件事。另一个需求——"让模型读 PDF"——是同一条线上的第二件事，后面单独开一篇。

## 输入和输出

先界定两头：

- **输入**：我和模型的聊天内容，或者我写的一份 Markdown 大纲。越结构化越好，但第一步不追求完美。
- **输出**：一个能打开、能讲的 PPT 文件。要么是 PowerPoint 的 `.pptx`，要么是 Beamer 编译出来的 PDF。

有一点要先说清：用哪个模型（qwen3.8、gemma4，还是 deepseek 之类）和"怎么产出 PPT"是两件事。模型只负责"写内容"，真正决定产出形态的是下面要说的"渲染管线"。所以换模型基本不改架构，后面文章里模型可以随便换着试。

## 三条路径

核心差别在中间那一步——怎么把模型写的东西变成真实的幻灯片文件。

| 路径 | 模型产出 | 本地渲染器 | 最终文件 | 适合 |
|---|---|---|---|---|
| A · Beamer | Beamer 的 `.tex` 源码 | `xelatex` 编译 | PDF | 系列讲义、公式多、要版本管理 |
| B · Markdown→PPTX | 结构化 Markdown / JSON | `pandoc` 或 `python-pptx` | `.pptx` | 一次性汇报、要交给别人、PowerPoint 里继续改 |
| C · 工具调用 | 函数调用指令 | MCP / Agent 边聊边建 slide | `.pptx` | 想"聊着做"、逐步调版式 |

**路径 A**：模型直接写 Beamer 源码，本机 `xelatex` 一编译就是 PDF。你本来就用 Beamer 做系列，这条最顺，公式和中文都没问题，文件还能进 git。缺点是精细版式得改 LaTeX 模板，不如 PowerPoint 直观；而且得先装好 TeX 发行版。

**路径 B**：模型写一份带结构的 Markdown（每张 slide 一个二级标题，或一份 JSON 的 slide 列表），再用 `pandoc`（配一个 `reference.pptx` 当模板）或 `python-pptx` 脚本转成 `.pptx`。好处是产出物是原生 Office 文件，能直接交给别人、能在 PowerPoint 里接着改。坏处是 `python-pptx` 默认样式朴素，想好看要自己写模板；`pandoc` 对复杂版式支持有限。

**路径 C**：把"建一张 slide"封装成工具（比如用 `python-pptx` 包一个 MCP server，或者 WorkBuddy 里的 pptx 能力），让模型在对话里分步调用、一张张搭。最贴近"边聊边做"，版式控制也最细。代价是部署最重——要本地起一个 MCP server，而且本地模型的函数调用稳不稳（qwen3.8 能不能可靠 tool-calling）得先验证。

## 我初步倾向哪条

三条里没有绝对好坏，取决于那次 PPT 是"系列讲义"还是"一次性汇报"。

我更想先走 **B**，原因是它和我两种现有习惯都能接上：同一份模型写出的 Markdown，既能用 `pandoc` 走 Beamer 出 PDF（接上我现有的系列流程），也能用 `python-pptx` 出 `.pptx`（接上 PowerPoint 流程）。等于在模型和内容之间立一个"标准中间格式"，渲染器可换。等 B 跑通了，再视情况补 A（公式多的场合）或试 C（要反复调版式的场合）。

但这只是初步想法，没定。具体走哪条，得看后面实操顺不顺。

## 这篇文档拿来干什么

它是一份"目标文档"，不是实现文档。后面我会按这个系列一篇篇补：

1. 先验证 qwen3.8 在 Ollama 上跑这种任务的靠谱程度（尤其是长文本、中文、函数调用）；
2. 挑一条路径，写出本地转换脚本；
3. 把整套串成一个能反复用的个人 skill / agent / 工具，固化下来；
4. 再开"读 PDF"那一条。

踩的坑也记下来。
